# T14 / T15 — entiers 128 bits dans l'IR et le JIT (2026-11-28)

Statut : `TESTED` sur Linux x86-64, `rustc 1.95.0`. Base : `dev` @
`ba4633bfc62c1440db7597514e596da554fff6d4`. Branche : `feat/ir-i128-u128`.
Aucun gate n'est déclaré `PASS` : T14/T15 restent `PARTIAL`, ADR-010 n'est pas
ratifié et la couverture du langage reste incomplète.

## Périmètre livré

- IR **`ravum-ir-1.10`** : `Ty::I128`/`Ty::U128`, taille et alignement 16,
  `Const::Wide { ty, bits }` sans conversion par `i128`, validation typée
  renforcée (constantes, copies, casts, opérations, mémoire, appels, retours).
- Lowering des littéraux et motifs 128 bits, y compris `i128::MIN` et
  `u128::MAX`, locales, paramètres, retours, références, structs, tableaux,
  tuples, enums et `Option`/`Result` à charge utile 128 bits.
- Interpréteur exact : `Val::U128(u128)`, opérations checked/wrapping/
  saturating, overflow, divisions/reste, shifts, comparaisons, casts avec
  saturation Rust, impression et mémoire little-endian 16 octets. Les mots de
  tas utilisent désormais des API `to_word`/`from_word` faillables : un entier
  large est refusé, jamais tronqué.
- JIT Cranelift : ABI paire 64 bits (`enable_llvm_abi_extensions`), constantes
  reconstruites par `iconcat`, zéro/trap wide, additions/soustractions avec
  overflow natif, helpers hôtes exacts et sans allocation pour multiplication,
  division/reste et conversions flottantes non abaissables en I128 par cette
  version de Cranelift. Impression et `to_string` transportent les deux mots.
- Refus explicite, jamais de troncature : `Vec<i128/u128>`, clés/valeurs de
  `Map` et valeurs d'`Arena` 128 bits. Les conteneurs du tas restent motivés par
  des mots 64 bits dans l'IR 1.10 ; les agrégats fixes utilisent la mémoire.

## Preuves exécutées

Commandes ciblées :

```text
cargo test -p ravum-lang-jit --test i128 -- --nocapture
cargo test -p ravum-lang-cli --test jit_i128_rustc -- --nocapture
cargo test -p ravum-lang-ir --tests -- --test-threads=2
```

Résultats :

- Différentiel large : **4 658 programmes**, **296 traps**, aucune divergence
  entre interpréteur, JIT et `ravum-core-machine` ; bornes, divisions, shifts,
  casts, NaN/infinis et saturations compris.
- Oracle rustc : le même programme est exécuté par `ravum-lang run`, par
  l'interpréteur et par le JIT ; sortie standard **identique octet pour octet**
  sur appels larges, références, agrégats, retours, shifts et casts.
- Le canari du corpus `o3-u128-max` n'est plus un refus : il est exécuté par les
  trois moteurs. Le recensement `ir_refusal_census` passe de **120/161 à
  121/161** programmes `run-pass` abaissés.
- Suites `ravum-lang-ir`, `ravum-lang-jit` et `ravum-lang-cli` : exit 0,
  aucune défaillance (tests ignorés de longue durée conservés comme tels).
- `cargo clippy --workspace --all-targets --jobs 2 -- -D warnings` : exit 0.
- `cargo run -p ravum-conformance -- run --verify-build` : **851 cas, 849
  PASS, 0 FAIL, 2 SKIP Windows, 0 NOT_RUN** ; build `perimeter=326/326`,
  `verified=136`, `implicit=190`, `failed=0`, `build_verified: true`. Les
  anciens chiffres 503 d'autres documents sont une baseline antérieure, pas
  la mesure de cette campagne.
- Tests existants adaptés sans réduction d'exigence : les exclusions de refus
  `i128/u128` deviennent des positifs ; `Holder<u128>` devient un test positif
  de layout. Les refus de tas 128 sont ajoutés séparément.
- Adversariaux forgés : types d'objets/tas, casts invalides, constantes non
  canoniques, IR invalide rejetée par validation/JSON/interpréteur/JIT, État
  DSP sous-aligné (y compris digest inchangé), changement de signature lors
  d'un hot swap. Un appel à six paramètres larges force le passage par la pile
  des paires de registres.

## Limites et décisions humaines

- `Vec`/`Map`/`Arena` 128 bits : refus explicites dans ce lot. Leur stockage
  demande un contrat de mot large ou deux mots, avec ordre numérique des clés ;
  ce n'est pas déclaré complet.
- État DSP/hot swap contenant un entier 128 bits : refus explicite tant que le
  tampon hôte n'est garanti que sur 8 octets et qu'un schéma exige 16. Aucun
  pointeur sous-aligné n'est publié.
- Les constantes sémantiques `u128` au-dessus de `i128::MAX` restent refusées
  explicitement : `ConstValue::Int(i128)` est une frontière lossy du frontal,
  à traiter sans la faire disparaître.
- `assert`/`assert_eq` : toujours en attente du choix du responsable entre le
  texte STD-8.1 et la sortie rustc.
- E/S hôte dans l'IR : toujours exclues par conception.
- ADR-010 : toujours `PROPOSED` ; ratification humaine requise pour T14 `PASS`.
- Helpers hôtes 128 : code Rust audité par les tests différentiels, mais aucune
  qualification formelle de traduction ni audit externe n'est revendiquée.
