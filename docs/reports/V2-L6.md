## Objectif et périmètre

Faire tourner une application `.rv` (HTTP + SQLite) dans un **vrai
navigateur** : créer, lister, supprimer des notes par la page, vérifier
l'état SQLite, et prouver que le test échoue sans serveur.

## Modification

| Fichier | Rôle |
|---|---|
| `packages/http-notes-web/` (nouveau) | serveur `.rv` : `GET /` (page HTML + JS), `GET /notes`, `POST /notes`, `POST /notes/delete` ; notes dans un fichier SQLite passé en argument ; `listening <port>` sur stdout |
| `scripts/e2e-browser/notes.mjs` (nouveau) | pilote Chromium via Playwright ; aucune dépendance ajoutée au dépôt |
| `.github/workflows/e2e-browser.yml` (nouveau) | **manuel seulement** (`workflow_dispatch`) : construit `ravum-lang` et la bibliothèque SQLite native, installe Playwright hors du dépôt, lance le test |

**Écart de périmètre** : le plan prévoyait `packages/http-notes/**`. Une
dépendance ne peut pas remonter au-delà du dossier parent du paquet
(`E-MOD-PATH-ESCAPE`) : un paquet dans `packages/http-notes/web` ne peut pas
dépendre de `packages/sqlite`. Le serveur est donc un paquet frère,
`packages/http-notes-web`. `packages/http-notes` est inchangé.

## Tests (11 vérifications, toutes dans Chromium)

Positifs : page servie par le serveur `.rv` ; liste vide au départ ; deux
ajouts listés ; texte `<b>not bold</b> & "quotes"` gardé tel quel, sans
injection HTML ; suppression ; base SQLite identique à la liste affichée.
Négatifs : note vide refusée, erreur visible, rien d'ajouté ; id invalide
→ 400 ; id inconnu → 404 ; **contrôle négatif** : serveur tué, la page ne se
charge plus (le test ne peut pas être vert sans serveur).

Le contrôle négatif a trouvé un vrai point : **tuer `ravum-lang run` ne
tue pas le binaire qu'il a lancé** (le serveur continuait de répondre). Le
test construit donc avec `build` et lance le binaire lui-même. Le
comportement de `run` (pas de transmission du signal à l'enfant) est à
décider : documenter ou corriger.

## Commandes

```text
cargo build -p ravum-lang-cli
ravum-lang fmt --check packages/http-notes-web
NODE_PATH=$(npm root -g) node scripts/e2e-browser/notes.mjs
```

Sortie (SHA de départ + ce changement) : 11 PASS, `e2e-browser: all checks passed`.

## Limites

- Un seul navigateur (Chromium), une seule plateforme (Linux).
- Le workflow CI n'a **pas** été exécuté (`NOT_RUN`) : il est manuel et
  n'existe que sur cette branche.
- Le serveur est séquentiel (une connexion à la fois, STD-19.8) et sans
  authentification : boucle locale seulement.
- Playwright est installé au run (npm, licence Apache-2.0) : pas une
  dépendance du dépôt, mais une dépendance d'outillage CI à valider.
