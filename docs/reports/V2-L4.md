## Tests

1. `the_example_block_equals_the_reference_and_the_interpreter` : sinus
   440 Hz, 4 800 échantillons, blocs de 64 à 48 kHz sur `WavHost` via le JIT ;
   sortie = référence Rust = interpréteur de l'IR, **bit à bit**.
2. `a_hot_gain_edit_is_adopted_at_a_block_boundary_without_allocation` :
   48 000 échantillons ; édition gain 2,0 → 1,0 publiée après le bloc 300,
   adoptée au bloc 301 (échantillon 19 264) ; sortie = référence avec
   changement à cet échantillon et **état du filtre conservé**, bit à bit ;
   contrôle négatif : un état remis à zéro donnerait une autre valeur ;
   **0 allocation et 0 libération** dans `process`.

## Mesure du fondu (voie JIT)

L'hôte JIT bascule à une frontière de bloc, **sans fondu (0 trame)**. Saut
mesuré à la bascule : |Δy| = **0,001620**, pour un pas maximal de **0,055780**
dans le signal stable : le filtre IIR lisse le changement de gain, aucun
saut plus grand que ceux du signal (vérifié par le test). Mesure valable pour
ce signal, ce filtre et cette édition seulement.

## Limites

- **Voie `cdylib`** (`build --emit dsp-block`, hôte `ravum-patch-host`) :
  ce bloc n'y est **pas** chargeable, son état `{ y }` n'est pas l'état
  ABI 2 `{ z1, z2 }` (`E-DSP-STATE-TYPE`). Il faut l'ABI 3 (RFC-DSP-ABI-2,
  chantier L5b). Le fondu de cet hôte (`MAX_FADE_FRAMES`, 256 trames par
  défaut) n'est donc toujours **pas** mesuré sur un bloc `.rv`.
- Hors ligne seulement (WAV) ; l'hôte `cpal` a déjà été exécuté sur
  périphérique pour un autre bloc (V1-A2/A3), pas pour celui-ci.
